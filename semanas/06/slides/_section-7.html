¿Claude Code maneja un browser? → De fábrica, no → corresponde MCP

Con la extensión Claude in Chrome, sí — pero necesita plan pago, y por dentro también es un MCP server (aparece en /mcp como claude-in-chrome). Playwright es la opción portable: cualquier host, sin plan, headless incluido.

Playwright MCP expone ese browser controlado como tools: un server local, que corre en tu máquina hablando por Stdio. Lo conectamos a un proyecto y lo ponemos a trabajar.

Marco del primer demo. La pregunta cero da "de fábrica, no" (CC no trae browser propio) → corresponde MCP. Con Claude in Chrome y plan pago sí se puede, y esa extensión es, por dentro, también un MCP server. Playwright es la alternativa portable. Codex CLI y OpenCode tampoco traen browser propio. Se planta el eje de las dos secciones: este es un server LOCAL, transport Stdio. El próximo será remoto.

"Primer demo. Apliquemos la pregunta cero: ¿Claude Code maneja un browser? De fábrica, no — sabe correr Bash, pero no renderiza páginas, no clickea, no completa forms. Con la extensión Claude in Chrome y un plan pago sí se puede, y por dentro esa extensión es, también, un MCP server. Playwright es la alternativa portable: corre en cualquier host, sin plan, hasta headless — y lo mismo les pasa con Codex CLI y OpenCode, que tampoco traen browser de fábrica. El server que usamos es Playwright MCP: expone ese browser controlado como tools. Y fíjense en algo que vamos a contrastar con el próximo demo: este es un server local, corriendo en su propia máquina, comunicándose por Stdio, sin red. Vamos a conectarlo a un proyecto y verlo actuar."

Una línea, y queda.

Local, por Stdio: sin red, sin auth.

$ claude mcp add playwright -- npx @playwright/mcp@latest
local · Stdio El server corre como subproceso en tu máquina. npx baja el paquete la primera vez; después arranca solo en cada sesión.
sin red Los mensajes JSON-RPC viajan por stdin/stdout. No hay URL, no hay auth: el server es local.

Install del server local. Lo importante para el contraste con §8: acá hay un comando que arranca un proceso local (Stdio, sin red, sin auth). En el remoto va a haber una URL y OAuth.

@playwright/mcp todavía habla la revisión de protocolo 2025-11-25, así que acá el cliente usa el handshake initialize en vez de server/discover — el patrón del intercambio es el mismo (por eso la animación del §5 usó un server genérico).

"Se agrega con el mismo comando del bloque de harnesses: claude mcp add playwright, guión guión, npx arroba playwright barra mcp arroba latest. Una línea, y el server queda corriendo como un subproceso en tu propia máquina — transport Stdio. npx baja el paquete la primera vez y después lo arranca solo cada vez que abrís una sesión. Los mensajes viajan por stdin y stdout, sin red. No hay URL ni autenticación, porque el server vive con vos. Guarden esa imagen — el próximo demo es exactamente lo contrario."

Demo en vivo, terminal + browser lado a lado. Click cada beat.

Dos casos: lectura (traer datos de una página) y acción (completar un form). Antes de arrancar, confirmar que el server está conectado con /mcp. El alumno tiene que ver el browser moverse solo.

"Vamos al vivo. Antes de nada, /mcp para confirmar que playwright está conectado. Primer caso, lectura: le pido que abra Hacker News y me traiga los títulos de los cinco primeros posts — van a ver al agente decidir que necesita el browser, navegar, leer la página, y volver con los títulos, sin que yo copie ni pegue nada. Segundo caso, acción, que ya tiene efecto: le pido que vaya a un form público y lo complete con datos de prueba. Mismo patrón, pero ahora el agente identifica los campos, los llena uno por uno y hace submit."

Acciones (copiables):

Paso 1 — Lectura

  • En Claude: /mcp → confirmar playwright connected
  • En Claude: "abrí news.ycombinator.com y traeme los títulos de los 5 primeros posts"
  • Mirar: el browser se abre solo y navega
  • Mirar: el agente llama browser_navigate y browser_snapshot
  • Mirar: los 5 títulos vuelven a la conversación, sin copy-paste

Paso 2 — Acción

  • En Claude: "andá a httpbin.org/forms/post y completá los campos con datos de prueba"
  • Mirar: el agente identifica los campos del form
  • Mirar: llama browser_type campo por campo
  • Mirar: hace browser_click en submit
  • En Claude: el agente reporta qué se envió

Plan B: screenshots pre-armados de las dos corridas (lectura y acción), si el browser no abre en vivo.

Qué viste.

El mismo intercambio, en concreto.

→

Lo que importa no es el cómo de Playwright. Es la forma del intercambio — la misma para cualquier server. Cambia qué hace; no cambia cómo se habla.

Cierre del demo local. Mapea explícitamente al intercambio de §5. El takeaway no es Playwright — es la forma del intercambio, que se repite igual. Bridge a §8: el mismo patrón, pero con un server remoto.

"¿Qué vieron, en el fondo? Exactamente el mismo intercambio: el server expuso sus capacidades, el cliente las descubrió y armó el contexto, el modelo las invocó con argumentos concretos, y el resultado volvió a la conversación. Ese es el patrón. Y lo que tienen que sacar no es cómo funciona Playwright — eso lo busca el agente. Es la forma del intercambio, que es idéntica para cualquier server: cambia qué hace, no cambia cómo se habla. Esto fue un server local, corriendo en la máquina. Ahora veamos exactamente el mismo patrón, pero con un server que vive afuera, en internet."
