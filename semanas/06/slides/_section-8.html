Un remoto se agrega distinto.

Mismo comando base, pero apunta a una URL — y la auth es OAuth.

Claude Code claude mcp add --transport http linear-server https://mcp.linear.app/mcp

Escribe en .mcp.json o ~/.claude.json, según el scope. OAuth con /mcp en la sesión, o claude mcp login linear-server desde la shell.


"mcpServers": {
  "linear-server": {
    "type": "http",
    "url": "https://mcp.linear.app/mcp"
  }
}
Codex codex mcp add linear --url https://mcp.linear.app/mcp

Escribe en ~/.codex/config.toml. Dispara OAuth al agregar; re-login con codex mcp login linear.


[mcp_servers.linear]
url = "https://mcp.linear.app/mcp"
OpenCode opencode mcp add

Interactivo: elegís remote y pegás la URL. Escribe en opencode.json. OAuth con opencode mcp auth linear (o automático en el primer 401).


"mcp": {
  "linear": {
    "type": "remote",
    "url": "https://mcp.linear.app/mcp"
  }
}

Los tres guardan lo mismo: una URL. Y los tres piden OAuth — el token queda guardado y se renueva solo.

Espejo de §6.2, ahora con un server remoto. Claude Code: claude mcp add --transport http <nombre> <url> es la forma canónica; sin --transport http asume Stdio. Codex: codex mcp add <nombre> --url <url> dispara OAuth en el momento si el server lo soporta; re-login con codex mcp login <nombre>. OpenCode: opencode mcp add es un asistente que pregunta remote/local y la URL; auth con opencode mcp auth <nombre> o automática al primer 401 (la forma con flags existe solo en versiones recientes, no se enseña). Linear también ofrece un endpoint de solo lectura, mcp.linear.app/mcp/readonly — el alcance mínimo de §6.12.

"Agregar un server remoto es la misma idea que agregar uno local, con dos cambios. En Claude Code: claude mcp add, pero con transport http, y en vez de un comando, la URL de Linear. En el JSON queda type http, con url, en vez de command y args. En Codex: codex mcp add linear, con la flag url; en Codex, igual, escribe una tabla mcp_servers en su config.toml, ahora con url en lugar de command. En OpenCode: opencode mcp add te pregunta remote y la URL, y queda en opencode.json como type remote. Los tres guardan lo mismo que con Playwright — un nombre y cómo llegar al server — solo que ahora es una URL en vez de un comando. Y como es un servicio de terceros con tus datos, los tres piden OAuth: en Claude Code con barra mcp o claude mcp login; en Codex, codex mcp login; en OpenCode, opencode mcp auth. Te logueás en Linear una vez, el token queda guardado y se renueva solo — no lo pegás a mano en ningún lado."

Dos casos sobre un server remoto: lectura (buscar y resumir issues) y acción (crear un issue). El alumno tiene que ver que es el mismo patrón que Playwright, con datos que viven afuera.

"Al vivo, mismo molde que antes. Antes de nada, barra mcp para confirmar que linear-server está conectado y autenticado. Primer caso, lectura: le pido que busque en Linear los issues abiertos que tengo asignados y me los resuma — el agente usa los tools de Linear para buscar, leer los issues y devolver el resumen, con datos que vienen del workspace, no de la máquina. Segundo caso, acción: le pido que cree un issue nuevo. El agente llama el tool de crear y el issue aparece en Linear, en vivo. Mismo patrón que el form de Playwright — cambia el dominio, no el intercambio."

Dos servers, dos transports, un patrón.

Playwright · local · Stdio

Corre en tu máquina, como subproceso. Sin red, sin auth. Lo arranca un comando.

en el JSON"type": "stdio"

Linear · remoto · HTTP

Vive en internet, hosteado. Te conectás por red, con OAuth. Lo señalás con una URL.

en el JSON"type": "http"

Cambia dónde vive el server y cómo te conectás. El intercambio es idéntico: el server expone, el cliente descubre, invoca, el resultado vuelve.

Cierre del bloque de demos y del arco de los dos transports. La conclusión que se llevan: el transport (local/remoto) cambia la plomería de conexión, pero el patrón de intercambio MCP es el mismo. Esto cierra §3 (dos transports) con evidencia.

"Y este es el cierre de los dos demos. Pusimos lado a lado un server local y uno remoto. Playwright: local, Stdio, corre en tu máquina, sin auth, lo arranca un comando, y en el JSON queda type stdio. Linear: remoto, HTTP, vive en internet, OAuth, lo señalás con una URL, y en el JSON queda type http. Lo que cambia entre los dos es dónde vive el server y cómo te conectás — la plomería. Pero el intercambio, lo que pasa una vez conectados, es idéntico: el server expone sus capacidades, el cliente las descubre, las invoca, y el resultado vuelve a la conversación. Un solo patrón, para cualquier server, viva donde viva. Eso es MCP."
